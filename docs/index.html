0. Apigee L7 SNI-routing proxy

No gcloud for Apigee proxies — management API (or apigeecli). Bundle = a zip whose top dir is apiproxy/.

1. App-LB PSC tier (Apigee → PSC → internal App LB → Internet NEG → origin)

The documented, working "Apigee over PSC to internet origins" path.

2. True L4 SNI router (internal proxy NLB + TLS routes, TLS-passthrough)

This SDK's gcloud lacks target-tcp-proxies --load-balancing-scheme and tls-routes import has no targetProxies — so the backend-service-less proxy and the TLS route go through REST.

Public variant: same, but --load-balancing-scheme=EXTERNAL_MANAGED on the backend services + target proxy, a public --address, and a forwarding rule without a subnet → test from anywhere with curl --resolve <sni>:443:<public-VIP>.

3. Hybrid NEG per host (PSC-eligible; internet NEG is banned behind a PSC-published proxy NLB)

Pin each origin's current public IP — they rotate, so this is demo-grade.

4. Private DNS so Apigee sends SNI=FQDN into the L4

Caveat (verified on the trial org): a private zone bound to the authorized network is not resolved by Apigee's managed tenant without explicit DNS peering (a Cloud DNS peering zone + roles/dns.peer for Apigee's service agent). With a plain zone, Apigee resolved the FQDN publicly and bypassed the L4.
